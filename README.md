BenchLog は、ベンチプレス中級者（70〜90kg帯）向けの記録・分析・メニュー提案アプリです。

## 🧭 利用方法

BenchLog の基本的な利用手順は以下のとおりです。

---

### 👤 1. ユーザー登録・ログイン

- 新規登録ページからユーザー情報を入力してアカウントを作成します。  
- ログインすると、ホーム画面に **Today’s Menu（今日のメニュー）** が表示されます。  
- 記録が 0 件の場合は「最初の記録を追加する」カードを表示し、迷わず利用を開始できます。

---

### 🏋️ 2. トレーニング記録を追加する

1. ホーム画面の「記録を追加する」ボタンから遷移  
2. 以下の項目を入力  
   - 日付  
   - 重量（kg）  
   - 回数  
   - セット数  
3. 「保存する」ボタンで記録を登録  

登録された記録から推定1RMが自動計算され、グラフやメニュー提案に反映されます。

---

### 📊 3. 分析画面で成長を確認する

- 画面下部フッターの分析アイコン（📊）から遷移できます。  
- 分析画面では以下を確認できます。  
  - 推定1RMの推移グラフ（Chart.js）  
  - 週間総ボリューム  

自分の成長が視覚的にわかり、モチベーション維持につながります。

---

### 📝 4. 軽め / 通常 / 重めメニューを切り替える

- ホーム画面の Today’s Menu では、  
  - 通常メニュー  
  - 軽めメニュー（フォーム重視）  
  - 重めメニュー（刺激を入れる）  
  を切り替えて確認できます。  

「今日は軽めにしたい」「今日は攻めたい」といった状況でも、迷わず強度を選べるようにしています。

## ✨ 工夫したポイント

### ■ ① 中級者向けに特化した「今日の最適メニュー」ロジック

ベンチプレス中級者（70〜90kg帯）は、日ごとのコンディション差が大きく、

- 「今日は重くいっていいのか？」
- 「軽めにしたほうが良いのか？」

を判断しづらい課題があります。

そこで BenchLog では、次の仕組みで “今日のメニュー選び” をサポートします。

- 記録データから 現在の力の目安を自動算出  
- 2.5kg刻みの丸め処理で実際のジム環境に合わせた重量表示  
- 軽め（フォーム重視）／通常／重め（刺激を入れる）の3パターンを切り替えて確認できる

中級者が最も迷いやすい「今日のメニュー選び」をアプリが代行する設計にしました。

---

### ■ ② 使いやすさを重視したスマホ最適化 UI

ジムでスマホを片手で操作する前提で、UI を徹底的にスマホ向けに調整しました。

- max-width を **480px** に固定し、どの端末でも見やすい幅に統一  
- ボタンサイズ・余白を調整し、誤タップを防止  
- 初回ユーザーには「最初の記録を追加する」カードを表示し、迷わない導線を設計  
- 黒ベースの配色で、暗いジム環境でも見やすいコントラストに調整  

“初めて使う人でも迷わず操作できること”  
“トレーニング中でもサッと操作できること”  
を最優先にしています。

力の変化がわかるグラフで見える化し、成長を直感的に理解できるようにしました。

- nil が混ざってもグラフが落ちないように安全設計  
- スマホでも見やすいグラフサイズ・余白を調整  

記録を続けるモチベーションにつながる機能として設計しています。

## 🔧 改善点（ロジック面）

### 🚩 現状の課題

BenchLog ではメニュー提案を自動化しているが、以下のロジック面での課題が残っています。

- 1RM 抽出ルールがページごとに異なり、一貫性がない  
- アップセットが混在するとトレンド判定が不安定  
- 推定1RMの小さなブレに敏感で、メニューが上下しやすい  
- 軽め／重めメニューが標準メニューに依存しており、基準が揺れる  
- nil処理・丸め処理が機能ごとにバラバラ  
- UI とロジックで小数点処理が異なり、表示と計算結果が一致しない  

そのため「中級者の迷いを減らす」という目的に対し、  
**メニューの安定性に課題がある状態です。**

---

## 🎯 改善方針（ロジックの 3 層分離）

今後の拡張性・保守性を高めるため、ロジックを次の3層に分離予定です。

---

### ① データ層（1RM 抽出の統一）

- 1日の **最後のセットのみ** を採用（最も実力を反映しやすい）  
- 30kg未満など誤差が大きいデータを除外  
- nil処理を統一し、「計算できないデータ」を明確に扱う  
- 丸め処理（小数点の扱い）を全ページで共通化  

👉 どの機能でも同じ1RMが算出される安定した土台を作る。

---

### ② 分析層（トレンド・ボリューム判定の一元化）

- データ層の値から、最新3件の1RMを使って  
  **上昇 / 横ばい / 下降** を判定  
- 閾値はジム環境に合わせて **2.5kg** に統一  
- 週間ボリュームから疲労度の目安も判定  

👉 分析ロジックが UI から独立し、どこから呼んでも正しく動く状態にする。

---

### ③ メニュー層（Today’s Menu 生成）

- 分析結果に応じて Today’s Menu を生成  
  - 上昇 → やや攻めたメニュー  
  - 横ばい → 標準メニュー  
  - 下降 → 回復寄りメニュー  
- 軽め・重めメニューの分岐もこの層で一元管理  
- UI とロジックの丸め処理も統一  

👉 中級者にとって “揺れないメニュー提案” を実現する。

---

## 🧭 将来的に検討している改善（本質的な安定化）

BenchLog では、より安定したメニュー提案を実現するために、  
**“測定用セット” と “通常トレーニング（ボリュームセット）” を分けて扱う設計** を検討しています。

### ■ 測定用セット（1〜3RM）
- 実力（その日の最大筋力）を測る目的  
- 1〜3回で行う高重量セット  
- 推定1RMの基準値として扱う  

### ■ 通常トレーニング（ボリュームセット）
- 今日のメニューを実際に実行するセット  
- 回数が多いため、1RMの指標には向かない  
- 1RMには反映せず、疲労状況（ボリューム計算）にのみ使用  

---

### 🔍 この分離により改善される点

- **1RM の基準値が毎回変動しない**  
  → 軽めの日の記録が基準を下げることがなくなる  

- **メニューが日替わりで暴れなくなる**  
  → 今日軽めのセットをしても、1RMが急落しない  

- **中級者が感じやすい不安（“今日は何をやるべき？”）が減る**  
  → メニューが安定し、迷いが減る  

👉 筋トレ理論に基づいた “正しい1RM管理” に近づく設計になる。
