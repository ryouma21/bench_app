# アプリケーション名
BenchLog（ベンチログ）
# アプリケーション概要
ベンチプレス中級者（70〜90kg帯）向けの 記録・分析・成長サポートアプリです。
Epley式による推定1RM算出、週間ボリュームの可視化、直近のデータから自動で「今日の最適メニュー」を提案することで、ユーザーの迷いを減らし、継続しやすい環境を提供します。

# アプリケーションを作成した背景
ベンチプレス100kgを目標にトレーニングを続ける中で、ノートやスマホのメモでは記録が埋もれてしまい、  「自分が伸びているのか？」  「次に何をすべきか？」  が判断しづらい課題がありました。  
また、情報収集をしても YouTube・SNS には上級者向けの内容が多く、初心者向けの動画や記事もたくさんあるものの、情報が多すぎて整理しづらく、「何が正解なのか？」が分からないまま、あれこれ試して迷ってしまう という悩みもありました。
特に 70〜90kg帯の中級者が参考にできる “ちょうど良い指針” はほとんど存在しておらず、自分に合った練習内容を見つけるのが難しいと感じていました。
そこで、同じレベルのユーザーが、記録を残しやすく、フォームの状態を振り返れ、成長の流れが見えて、今日のベストな練習内容まで迷わず決められる。  
そんなアプリが必要だと考え、本アプリを開発しました。
# 実装した機能（画像付き）
### ◆ Today’s Menu（メニュー提案）
ユーザーの最新の記録から推定1RMを算出し、「今日の最適メニュー」を自動生成します。
中級者が迷いやすい「今日は何をやればいいのか？」を解消するための中核機能です。

### ◆ 初回ユーザー画面（記録0件の場合）
まだ記録が1件もないユーザーには、最初の導線として「記録を追加する」カードを表示します。
初心者〜中級者でも迷わず始めやすい UI を意識しています。

### ◆ 記録追加フォーム
日付・重量・回数・セット数を入力して、トレーニング記録を追加できます。
エラー表示や日本語化、スマホ最適化された入力フォームを実装しています。

### ◆ 代替メニュー（軽め・重め）の自動提案
ユーザーの推定1RMと当日のメニュー内容から、
「通常・フォーム重視（軽め）・刺激を入れる（重め）」の3パターンを自動生成します。
中級者が感じやすい「今日は軽めにしたいけど、どれくらいが適切？」という迷いを解消する設計にしています。

### ◆ 記録一覧
最新のトレーニング記録を一覧で確認できます。
ユーザーがすぐに前回の内容を振り返れるよう UI をシンプルにしています。

### ◆ 推定1RM推移グラフ（Chart.js）
推定1RMの変化をグラフで可視化します。
トレーニングの成長が直感的に理解でき、モチベーション維持にもつながる機能です。

# 実装予定の機能
・フォームチェック項目の登録  
肩の挙上／ブリッジの高さ／軌道の安定など、自己評価を記録し改善傾向を可視化。
・過去記録の比較ビュー  
任意の2日分の1RM・重量・回数・セット数を比較し、成長の差分を表示。
・記録検索（期間フィルタ）
特定期間（例：1週間、1ヶ月、3ヶ月）での記録をフィルタリング。
・SNS共有（1RM更新時のシェア）  
　モチベーション向上のため、1RM更新時に画像でシェアできる機能。

# 工夫したポイント

### ■ ① 中級者向けに特化した「今日の最適メニュー」ロジック
ベンチプレス中級者（70〜90kg帯）は、日ごとの調子の変動が大きく、  
「今日は重くいくべきか？軽めにすべきか？」を判断しづらい課題があります。

そこで以下を元に、メニュー提案ロジックを実装しました。

- 直近 3 回の推定 1RM から “上昇 / 停滞 / 下降” を判定  
- 週間ボリュームに応じた負荷コントロール  
- 2.5kg刻みの丸め処理でジムで扱いやすい重量に調整  
- 軽め（フォーム重視）／通常／重め（刺激を入れる）の 3 パターンの代替メニュー生成

中級者が最も迷いやすい「トレーニング内容の判断」をアプリが代行する点を重視しました。

---

### ■ ② 使いやすさを重視したスマホ最適化 UI
利用者がジムで片手で操作する状況を想定し、  
**スマホ前提の UI / レイアウト** を徹底しました。

- ボタンを大きく、押しやすい配置に調整  
- max-width を 480px に固定し、見やすさを統一  
- 最初の記録が 0 件のユーザーには “迷わない導線” を用意  
- 黒ベースの配色で暗いジム環境でも見やすく設計  

UX（ユーザー体験）の観点から、  
「初めて使う人でも迷わない」構造を意識しています。

---

### ■ ③ グラフによる成長の可視化（Chart.js）
推定 1RM の推移をグラフ化し、  
ユーザーが成長を直感的に理解できるようにしました。

- 直近の記録のみを抽出するスコープ  
- nil が混ざっても落ちない安全設計  
- スマホ最適化された表示  

記録をつけるモチベーションにつながるよう工夫しています。

---

### ■ ④ エラー表示や入力体験の改善（日本語化対応）
初心者でも扱えるように、入力画面の体験を細かく調整しました。

- エラー文を日本語化し、意味が分かるように変更  
- どの項目でミスが起きたのかすぐわかるよう UI を調整  
- 同一フォームを新規作成・編集で共通化し可読性を向上  

Rails の **部分テンプレート化** を意識して保守性を高めています。

# 改善点
🚩 現状の課題（ロジック面）

BenchApp ではユーザーの記録から自動でメニューを提案しているが、
以下の理由により メニューが安定しない問題 があった。

1RM 抽出ルールがページごとに異なり、一貫性がない

アップセットが混在し、トレンド判定が不安定になる

推定 1RM の小さなブレに過剰反応し、重量が上下しやすい

軽め／重めメニューが標準メニューに依存し、基準が揺れる

nil 処理や丸め処理が機能ごとに異なり、正しい比較ができない

UI とロジックで小数点処理が異なるため、表示と計算が一致しない

これらにより、中級者が求める「迷いを減らす」という目的に対し、
ロジックの安定感に課題があった。

🎯 改善方針（ロジックの 3 層分離）

ロジックの 安定性・保守性・拡張性 を高めるため、
以下の 3 層に責務を分離する方針で改善を進める。

### ① データ層（1RM 抽出の統一）

1RM を算出する前段階として、すべてのページ・機能で 同じ基準のデータ を扱えるようにする。

1日の 最後のセットのみ採用（実力が最も出やすい）

30kg 未満のセットなど誤差の大きいデータを除外

nil 処理の統一（推定不可のデータは明確に扱う）

小数点処理（丸め方）を 全ページで共通化

👉 どの機能でも同じ 1RM が算出され、信頼できる基準ができる。

### ② 分析層（トレンド・ボリューム判定の一元化）

データ層で整形された 1RM を使い、ユーザーの状態を“分析”するロジックを集約。

最新 3 件の 1RM から
上昇 / 横ばい / 下降 を判定

閾値は 2.5kg（ジムの最小プレート） に統一

週間ボリュームの判定もここに集約し、
回復状況や疲労感をロジックで判断

👉 分析ロジックが UI に依存せず、どこから呼んでも正しく動く。

### ③ メニュー層（Today’s Menu 生成）

分析結果から、ユーザーが迷わず取り組める
安定した Today’s Menu を作成。

上昇 → やや強度高め

横ばい → 標準メニュー

下降 → 回復より

軽め・重めメニューもここで一元管理

UI とロジックの丸め処理を統一し、表示差をなくす

👉 ユーザー体験として“揺れないメニュー”を提供できる。

🔧 将来的な改善（より安定した1RM管理に向けて）

筋力トレーニングの特性上、
普段のトレーニング（5〜10回）は 1RM を正確に反映しにくい。

そのため、以下の改善を検討中。

① 測定用記録（高重量セット）と通常記録を分離

測定用：1〜3回の実力判定

通常記録：今日のメニュー実行の記録

1RM計算は測定用のみ使用

② Today’s Menu の根拠値を安定化

軽めの日の記録で 1RM がブレない

メニューが毎日上下せず、ユーザーの迷いが減る

👉 中級者が安心して使える“安定した1RM管理”が可能になる。

✨ 改善による期待効果

どのページでも 一貫した1RM計算 が可能に

トレンド判定が安定し、メニューの上下ブレが消える

ユーザーが「このメニューで合ってる？」と迷う状況が減る

ロジック全体の 保守性・テスト性が向上


👉 BenchApp の目的である
「中級者の迷いを減らすメニュー提案」を、より高い精度で実現できる。
